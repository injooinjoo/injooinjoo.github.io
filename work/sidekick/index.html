Sidekick — AI Employees on Your Phone사이드킥 — 폰 속의 AI 직원

A phone app for hiring AI employees and handing them real work, with your approval before anything goes out. I built it alone with AI coding agents; the hard part was keeping them from bringing old code back.

AI 직원을 채용하고 실제 일을 맡기되, 밖으로 나가는 건 모두 내가 승인하는 폰 앱. AI 코딩 에이전트와 혼자 만들었고, 가장 어려웠던 건 에이전트들이 옛 코드를 되살리지 않게 하는 일이었습니다.

At a glance한눈에 보기

  1. 01Problem문제

    AI agents can already do real work, but using one means servers, API keys and a terminal. Most people who could use the help will never open a terminal.

    AI 에이전트는 이미 실제 일을 할 수 있지만, 쓰려면 서버, API 키, 터미널이 필요합니다. 도움이 필요한 사람 대부분은 터미널을 열 일이 없습니다.

  2. 02What I built만든 것

    A phone app where you hire AI employees, hand them a task and approve the result before anything is posted, sent or spent. Each user gets an isolated agent runtime.

    AI 직원을 채용하고 일을 맡긴 뒤, 무언가 게시·전송·결제되기 전에 결과를 승인하는 폰 앱. 사용자마다 격리된 에이전트 런타임을 둡니다.

  3. 03Where it is현재 상태

    Closed beta on TestFlight. 1,900+ commits and 1,600+ merged PRs in three months, with 5,600+ backend tests.

    TestFlight 비공개 베타. 3개월간 커밋 1,900개 이상, 머지된 PR 1,600개 이상, 백엔드 테스트 5,600개 이상.

01

Why build it왜 만들었나

Many people want to run a channel, a blog or a small shop on the side but can’t be on it every day. Agents could do much of that work. Setting one up was the barrier.

채널이나 블로그, 작은 가게를 부업으로 운영하고 싶지만 매일 붙어 있을 수 없는 사람이 많습니다. 그 일의 상당 부분은 에이전트가 할 수 있었습니다. 문제는 설정이었습니다.

The product definition: a Korean non-developer hires an AI employee on their phone and sees a first real result within ten minutes. Retention is a second real task for the same employee within a week.

제품 정의는 이렇습니다. 한국의 비개발자가 폰에서 AI 직원을 채용하고 10분 안에 첫 실제 결과를 본다. 리텐션은 일주일 안에 같은 직원에게 두 번째 일을 맡기는 것이다.

02

Delegate, work, approve맡기고, 일하고, 승인하고

Results come back as cards. Posts, messages and payments wait for the user’s approval.

결과는 카드로 돌아옵니다. 게시글, 메시지, 결제는 모두 사용자 승인을 기다립니다.

Each user gets an isolated runtime where every AI employee keeps its own profile, memory and tools. If isolation breaks, it fails closed.

사용자마다 격리된 런타임이 있고, AI 직원마다 자기 프로필, 메모리, 도구를 가집니다. 격리가 깨지면 닫힌 채로 실패합니다.

03

Building alone, with AI agentsAI 에이전트와 혼자 만들기

I built Sidekick with AI coding agents running in parallel, mostly Claude Code. About half of the commits are co-authored with Claude models.

사이드킥은 주로 Claude Code 같은 AI 코딩 에이전트를 병렬로 돌리며 만들었습니다. 커밋의 약 절반이 Claude 모델과의 공동 작성입니다.

Speed brought a new kind of bug: UI I had removed kept coming back. Parallel agents started from different base commits, merges asked for a union of old and new, and the tests still protected the old behaviour. Green tests said nothing about whether the product was current.

속도는 새로운 버그를 불렀습니다. 지운 UI가 계속 돌아왔습니다. 병렬 에이전트가 서로 다른 기준 커밋에서 출발했고, 병합은 옛것과 새것의 합집합을 요구했고, 테스트는 옛 동작을 지키고 있었습니다. 테스트 통과는 제품이 최신이라는 증거가 아니었습니다.

The fix was a release line with four rules.

해결책은 네 가지 규칙으로 된 릴리스 라인이었습니다.

  • One pinned base. Every agent works in an isolated worktree created from the same commit.하나의 고정된 기준. 모든 에이전트는 같은 커밋에서 만든 격리 worktree에서 일합니다.
  • Tests for what’s gone. Anything removed gets a test that proves it stays removed.없앤 것에 대한 테스트. 지운 것에는 계속 지워져 있음을 증명하는 테스트를 붙입니다.
  • History is evidence, not a base. Old branches are read for reference; only minimal changes are carried forward.과거는 근거일 뿐 기준이 아닙니다. 옛 브랜치는 참고용으로만 읽고, 최소한의 변경만 앞으로 옮깁니다.
  • Workers never deploy. Only one verified commit on main is released, one release at a time.작업 에이전트는 배포하지 않습니다. main의 검증된 커밋 하나만, 한 번에 하나씩 배포합니다.

Decisions결정

  • Decision결정

    Approval before anything goes out밖으로 나가기 전에는 반드시 승인

    Trust is the product. People delegate more once they know nothing is posted, sent or spent behind their back. It is less automatic than some tools promise, on purpose.

    신뢰가 곧 제품입니다. 몰래 게시·전송·결제되는 일이 없다는 걸 알면 사람들은 더 많이 맡깁니다. 일부 도구가 약속하는 것보다 덜 자동이지만, 의도한 것입니다.

  • Decision결정

    One isolated runtime per user사용자마다 격리된 런타임

    Agents run code and keep personal memory. Isolation had to fail closed, even though a shared service would have been simpler to run.

    에이전트는 코드를 실행하고 개인 메모리를 가집니다. 공유 서비스가 운영은 더 쉬웠겠지만, 격리는 실패해도 닫혀 있어야 했습니다.

Where it is now현재 상태

Sidekick is in closed beta on TestFlight, and I use it myself. The first cohort tests the two numbers that matter: a first real result within ten minutes, and a second real task within seven days.

사이드킥은 TestFlight 비공개 베타 단계이고, 저도 직접 씁니다. 첫 사용자 그룹으로 중요한 두 숫자를 검증합니다. 10분 안의 첫 실제 결과, 7일 안의 두 번째 실제 작업입니다.

What I learned배운 점

With AI agents, writing code stops being the bottleneck. Knowing which code is current becomes the job.

AI 에이전트와 일하면 코드 작성은 더 이상 병목이 아닙니다. 어떤 코드가 최신인지 아는 것이 일이 됩니다.

  • Keep the kinds of evidence apart. Passing tests, a working install, production behaviour and store review are four different claims.증거의 종류를 나눕니다. 테스트 통과, 설치된 앱의 동작, 운영 환경의 동작, 스토어 심사는 서로 다른 네 가지 주장입니다.
  • PM habits carry over. Defining activation and retention before writing code kept a fast solo project pointed at users.PM 습관은 그대로 통합니다. 코드를 쓰기 전에 활성화와 리텐션을 정해 둔 덕분에, 빠르게 움직이는 1인 프로젝트가 사용자를 향해 있을 수 있었습니다.
