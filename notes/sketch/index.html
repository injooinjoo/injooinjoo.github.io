Connecting a preference survey to a three-scene story이상형 설문을 세 장면의 이야기로 잇기

연, 스케치 · WEB · Published작성·공개 2026-10-21

A visual survey turns hard-to-describe romantic preferences into a story told across three scenes.말로 설명하기 어려운 이상형과 관계 취향을 시각적 설문과 세 장면의 이야기로 연결합니다.

The starting problem출발한 문제

Atmosphere and emotional comfort are hard to select from short text labels alone. Visual choices and narrative are connected so answering questions feels like part of the experience rather than disconnected data entry.좋아하는 사람의 분위기와 관계에서 편안함을 느끼는 순간은 짧은 텍스트만으로 고르기 어렵습니다. 질문에 답하는 시간이 결과와 동떨어진 입력 작업처럼 느껴지지 않도록, 시각적인 선택과 이야기를 한 흐름으로 묶었습니다.

Design choices중요한 설계 판단

Faceless sketches support appearance choices, while relationship answers shape scenes from a first meeting to everyday life. Generated images and recovery are handled alongside order state and stored results at the server boundary.외모 선택에는 얼굴 없는 스케치를 사용하고, 관계에 관한 답은 첫 만남부터 함께하는 일상까지 이어지는 장면에 반영합니다. 생성 이미지와 주문 복구는 설문 화면만의 문제가 아니므로 주문 상태·결과 저장·다시 열기를 서버 경계에서 함께 다룹니다.

What is implemented구현한 경험

  • A 19-question flow adapts examples to previous choices. Faceless pencil-sketch cards make appearance preferences easier to select.19문항을 한 단계씩 묻고 선택에 맞춰 예시를 조정합니다. 얼굴 없는 연필 스케치 카드로 외모 취향을 고르게 했습니다.
  • Answers shape a first meeting, a growing relationship, and an everyday moment. Configured environments connect paid orders to three images of the same character and per-scene PNG downloads.답변을 첫 만남·가까워지는 사이·함께하는 하루로 엮습니다. 설정된 환경에서는 결제 주문에 같은 인물의 세 장면 생성과 장면별 PNG 저장을 연결합니다.
  • Toss order, approval, lookup, and cancellation APIs use dedicated Redis storage so orders and results can be recovered.Toss 주문·승인·조회·취소와 전용 Redis 저장소를 분리해, 주문 상태와 결과를 다시 불러오는 흐름을 구현했습니다.

JavaScript · Node.js · Vercel Functions · Redis REST · Toss Payments · Playwright

Current scope현재 제공 범위

Public experience · test payments공개 체험 · 결제 테스트

Survey and story flow are available. The public site labels payments as tests with no actual charge. Per-order image generation depends on configuration; this does not establish live payment operation. Email delivery is unavailable.설문과 이야기 구성을 체험할 수 있습니다. 공개 화면은 결제 테스트·실제 청구 없음으로 안내합니다. 주문별 이미지 생성 코드는 설정에 의존하며, 실결제 운영을 뜻하지 않습니다. 이메일 발송은 미제공입니다.

Questions to verify next다음으로 확인할 질문

The public deployment uses test payments. Live sales need separate verification of merchant approval, confirmation/cancellation, result recovery, and actual generated-image quality. Email delivery is outside the current scope.공개 배포는 결제 테스트 모드입니다. 실제 판매로 전환하려면 전용 상점의 승인 범위, 승인·취소와 결과 복구, 실제 이미지 생성 품질을 별도로 확인해야 합니다. 이메일 발송은 현재 제공 범위에 포함하지 않습니다.

Source documents, implementation, and the public deployment were checked on 21 Oct 2026. This section records verification questions, not a committed release schedule.프로젝트 문서·소스·공개 배포를 2026.10.21 기준으로 대조했습니다. 다음 질문은 확인 과제이며 확정된 출시 일정이 아닙니다.
