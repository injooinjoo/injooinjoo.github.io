Building the intake-to-results flow before connecting analysis분석 기능보다 먼저, 입력에서 결과 탐색까지의 흐름 만들기

썸의 마음확인하기 · Project note프로젝트 노트 · 2026-10-21

A frontend prototype for entering relationship concerns and conversations, then exploring clues, wording, and next steps.관계 고민과 대화를 입력하고, 마음의 단서·보낼 말·다음 행동을 탐색하는 프런트엔드 프로토타입.

Drawings unfold slowly, one scene at a time.한 장면씩 천천히 그려집니다.

01The starting problem출발한 문제

When sharing relationship concerns, manageable questions matter more than a long form. The initial focus is preserving context when selecting files, editing answers, going back, or retrying preparation.관계 고민을 털어놓는 화면에서는 긴 입력 양식보다 한 번에 대답할 수 있는 질문이 중요합니다. 대화 파일을 고르다가 돌아오거나, 답을 수정하거나, 결과 준비가 실패할 때도 맥락을 잃지 않는 흐름을 먼저 다뤘습니다.

02Design choices중요한 설계 판단

Chat bubbles and selection interactions guide intake; results are organized into clues, wording, and next actions. This is a frontend prototype with fixed samples, so its state must not imply that submitted material was actually analyzed.말풍선과 선택 인터랙션을 단계별 질문에 연결하고, 결과는 마음의 단서·보낼 말·다음 행동으로 나눴습니다. 현재는 고정 샘플을 제공하는 프런트엔드 프로토타입으로, 입력 자료를 실제 분석했다는 인상을 주지 않도록 상태를 명시합니다.

03What is implemented구현한 경험

  • Chat bubbles, typing indicators, and selection animations guide stepwise questions. KakaoTalk TXT, pasted chats, and screenshot previews share one intake flow.말풍선·타이핑·선택 애니메이션으로 한 단계씩 질문하고, 카톡 TXT·붙여넣기·스크린샷 미리보기를 하나의 입력 흐름으로 묶었습니다.
  • Answer editing, back navigation, a purchase-confirmation demo, and preparation retries support interruptions and recovery.답 수정·이전 단계 복귀·구매 확인 체험·준비 실패 재시도로 중단과 복귀를 설계했습니다.
  • Three sample-coaching tabs connect to copy, print, and delete actions, with keyboard access and reduced-motion support.3탭 샘플 코칭에 문장 복사·인쇄·자료 삭제를 연결하고 키보드 접근과 움직임 감소를 지원합니다.

04Current scope현재 제공 범위

Public frontend prototype공개 프런트엔드 프로토타입

Results are fixed samples, not analysis of submitted material. AI, OCR, email, and real payments are not connected. Inputs stay in browser memory and disappear on reload.결과는 고정 샘플로 입력 자료의 분석 결과가 아닙니다. AI·OCR·이메일·실결제는 미연결입니다. 입력은 브라우저 메모리에서만 처리하고 새로고침하면 사라집니다.

05Questions to verify next다음으로 확인할 질문

Connecting AI, OCR, email, or payments first requires decisions about transfer/storage boundaries, failure and deletion handling, and evidence shown with results. Current inputs stay in browser memory and disappear on reload.AI·OCR·이메일·결제를 연결하려면 자료 전송과 보관 범위, 실패·삭제 처리, 결과의 근거 표시를 먼저 정해야 합니다. 현재 입력은 브라우저 메모리에만 머물고 새로고침하면 사라집니다.

Source documents, implementation, and the public website checked on 21 Oct 2026. These questions are verification tasks, not a committed release schedule.프로젝트 문서·소스·공개 웹을 2026.10.21 기준으로 대조했습니다. 다음 질문은 확인 과제이며 확정된 출시 일정이 아닙니다.
